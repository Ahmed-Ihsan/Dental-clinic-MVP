## 1. تسجيل الدخول والأدوار

### الأدوار المتاحة

| الدور | الصلاحيات |
|-------|-----------|
| **Admin** | الوصول الكامل — جميع البيانات، إدارة المستخدمين، الإعدادات |
| **Doctor** | فقط بياناته الخاصة — مواعيده، مرضاه، فواتير مواعيده |
| **Secretary** | جميع البيانات ما عدا الإدارة (إدخال المواعيد، الفواتير، المرضى) |

### سير تسجيل الدخول

```
1. إدخال اسم المستخدم + كلمة المرور
2. النظام يُرجع: username + role + professional_ids[]
3. يُخزّن في AuthContext → يحدد ما يظهر في القائمة الجانبية
```

### قائمة التنقل حسب الدور

- **Admin**: Dashboard · Appointments · Patients · Finance · Staff · Users · Settings
- **Secretary**: Dashboard · Appointments · Patients · Finance
- **Doctor**: Dashboard · Appointments · Patients

## 2. إدارة المستخدمين

> متاح فقط للـ **Admin**

| العملية | الخطوات |
|---------|---------|
| **إنشاء مستخدم** | زر "مستخدم جديد" → اسم مستخدم + كلمة مرور + دور → حفظ |
| **تعديل مستخدم** | زر "تعديل" → تغيير الدور / كلمة المرور / ربط ملفات طبية |
| **ربط ملفات طبية** | نافذة التعديل → قسم "ربط بملفات طبية" → ✓ checkbox (متعدد الاختيار) |
| **حذف مستخدم** | زر "حذف" → تأكيد (لا يمكن حذف حسابك الخاص) |

### منطق الربط

```
users.id ──1:N──► professionals.user_id
```

- مستخدم واحد (Doctor) يمكن ربطه بـ **أكثر من ملف طبي**
- كل ملف طبي له `user_id` يشير إلى حساب المستخدم
- عند تغيير ربط المستخدم → يُمسح `user_id` القديم ويُعيّن الجديد

## 3. الملفات الطبية

### إنشاء ملف طبيب

```
Staff → إضافة مهني جديد
  ├─ الاسم الأول
  ├─ اسم العائلة
  ├─ التخصص
  ├─ الهاتف
  ├─ البريد الإلكتروني
  └─ رقم الترخيص
```

### ربط بحساب مستخدم

> **هام**: الملف الطبي يُنشأ أولاً في Staff، ثم يُربط بحساب مستخدم في **إدارة المستخدمين**.

## 4. المواعيد

### إنشاء موعد (Admin / Secretary)

```
التقويم → اضغط على يوم فارغ
  ├─ اختر المريض (بحث ذكي)
  ├─ اختر الطبيب من القائمة
  ├─ حدّد وقت البداية والنهاية
  ├─ حدّد الحالة (مجدول / مؤكد)
  └─ حفظ
```

### إنشاء موعد (Doctor)

```
التقويم → اضغط على يوم فارغ
  ├─ اختر المريض
  ├─ الطبيب = مغلق تلقائياً 🔒 (ملفك الطبي)
  └─ حفظ
```

> **منطق الخلفية**: Doctor يُجبر `dentist_id` على أول ملف طبي مرتبط به. لا يمكنه تغيير الطبيب.

## 5. المرضى

### إنشاء مريض جديد

```
الطريقة 1: زر "إنشاء سريع" → تبويب "مريض جديد"
الطريقة 2: صفحة المرضى → إضافة
```

### ما يراه كل دور

| الدور | المرضى المرئيون |
|-------|-----------------|
| Admin | الكل |
| Secretary | الكل |
| Doctor | فقط المرضى الذين لديهم مواعيد مع ملفاته الطبية |

### منطق الفلترة

```sql
SELECT patient_id FROM appointments
WHERE dentist_id IN (professional_ids of current doctor)
```

## 6. الفواتير

### إنشاء فاتورة — الطريقة 1: الويزارد

```
"إنشاء سريع" → زيارة شاملة
  → يُنشئ تلقائياً:
    1. مريض (جديد أو موجود)
    2. علاج
    3. موعد (completed) ← مرتبط بالطبيب
    4. فاتورة ← مرتبطة بالموعد (appointment_id)
```

### إنشاء فاتورة — الطريقة 2: يدوية

```
صفحة الفواتير → إضافة فاتورة
  ├─ اختيار المريض
  ├─ اختيار موعد (اختياري)
  ├─ التكلفة / المدفوع / الخصم / المتبقي
  └─ حفظ
```

### ما يراه كل دور

| الدور | الفواتير المرئية |
|-------|------------------|
| Admin | الكل |
| Secretary | الكل |
| Doctor | فقط الفواتير المرتبطة بمواعيد ملفاته الطبية |

### منطق الفلترة

```
bill.appointment_id → appointment.dentist_id ∈ doctor.professional_ids
```

## 7. الزيارة الشاملة (Quick Visit Wizard)

### الخطوات الأربع

| الخطوة | المحتوى |
|--------|---------|
| 1 · بيانات المريض | اختيار مريض موجود أو إدخال جديد |
| 2 · الإجراء الطبي | نوع العلاج · التاريخ · الملاحظات |
| 3 · الفاتورة والدفع | التكلفة · المدفوع · الخصم · المتبقي |
| 4 · المراجعة والحفظ | عرض ملخّص → تأكيد |

### ما يُنشئه النظام عند الحفظ

```
1. POST /patients        (إذا مريض جديد)
2. POST /treatments      (الإجراء الطبي)
3. POST /appointments    (completed, dentist_id = professional_ids[0])
4. POST /bills           (linked to appointment_id)
```

> للطبيب: لا يمكنه تغيير الطبيب — يُربط تلقائياً بأول ملف طبي له.

## 13. تدفق البيانات

```
┌─────────────┐     ┌──────────────┐     ┌─────────────┐
│  users      │────►│ professionals│────►│ appointments│
│  (roles)    │     │ (user_id)    │     │ (dentist_id)│
└─────────────┘     └──────────────┘     └──────┬──────┘
                                                │
                  ┌─────────────┐               │
                  │   patients  │◄──────────────┘
                  └─────────────┘   (patient_id)
                         ▲
                         │
                  ┌─────────────┐
                  │   bills     │
                  │(appointment│
                  │    _id)    │
                  └─────────────┘
                         ▲
                         │
                  ┌─────────────┐
                  │ treatments  │
                  └─────────────┘
```

### ربط المستخدم بالملف الطبي

```
users.id = 5 (doctor)
         │
         ├──► professionals.user_id = 5  (id=3, طبيب أسنان)
         └──► professionals.user_id = 5  (id=7, جراح فك)
```

### فلترة المواعيد للطبيب

```sql
SELECT * FROM appointments
WHERE dentist_id IN (3, 7)  -- professional_ids of user 5
```

### فلترة المرضى للطبيب

```sql
SELECT DISTINCT patient_id FROM appointments
WHERE dentist_id IN (3, 7)
```

### فلترة الفواتير للطبيب

```sql
SELECT * FROM bills
WHERE appointment_id IN (
    SELECT id FROM appointments
    WHERE dentist_id IN (3, 7)
)
```

## API Endpoints Summary

| Endpoint | Method | Access | Description |
|----------|--------|--------|-------------|
| `/api/login` | POST | Public | Returns `professional_ids[]` |
| `/api/me` | GET | Auth | Returns user info + `professional_ids[]` |
| `/api/register` | POST | Admin | Create user with role |
| `/api/users` | GET | Admin | List all users |
| `/api/users/<id>` | PUT | Admin | Update role / password |
| `/api/users/<id>` | DELETE | Admin | Delete user (not self) |
| `/api/users/<id>/link-professional` | PUT | Admin | Link multiple `professional_ids[]` |

| `/api/appointments` | POST | Auth | Auto-assign dentist for doctors |

| `/api/bills` | GET | Auth | Filtered by role |

## ملاحظات تقنية للمشرف

### ربط حساب طبيب بملفاته الطبية

1. أنشئ الملفات الطبية في **Staff**
2. اذهب إلى **إدارة المستخدمين**
3. اضغط **تعديل** على حساب الطبيب
4. في قسم **"ربط بملفات طبية"** — ضع علامة ✓ على الملفات المطلوبة
5. اضغط **حفظ**

### سلوك حقل الطبيب في النماذج

| حالة الربط | سلوك الحقل |
|------------|-----------|
| لا يوجد ملف مرتبط | Dropdown فارغ — الطبيب لا يرى شيئاً |
| ملف واحد مرتبط | 🔒 مغلق تلقائياً باسم الطبيب |
| أكثر من ملف مرتبط | Dropdown مقيّد بملفاته فقط |

### ربط أكثر من ملف طبي بحساب واحد — كيف يعمل؟

**نعم** — عند ربط أكثر من ملف طبي (professional) بحساب طبيب واحد، يرى هذا الطبيب **البيانات المدمجة** من جميع الملفات المرتبطة به.

#### مثال

```
حساب الطبيب: dr_ahmed
  ├──► ملف طبي 1: "د. أحمد العلوشي" (تخصص: تقويم)  id=3
  └──► ملف طبي 2: "د. أحمد العلوشي" (تخصص: جراحة)  id=7
```

الطبيب يرى:
- **مواعيد** الموعدين اللي `dentist_id = 3` أو `dentist_id = 7`
- **مرضى** اللي عندهم مواعيد مع 3 أو 7
- **فواتير** المرتبطة بأي موعد من مواعيد 3 أو 7

#### البيانات المشتركة (Merge)

| البيانات | يشتركون؟ | التوضيح |
|----------|---------|---------|
| **المواعيد** | ✓ | يظهر مواعيد الطبيب 3 + مواعيد الطبيب 7 |
| **المرضى** | ✓ | يظهر جميع مرضى مواعيد 3 و 7 |
| **الفواتير** | ✓ | يظهر فواتير مواعيد 3 و 7 |
| **العلاجات** | ✓ | يظهر علاجات مرضى 3 و 7 |

#### البيانات المنفصلة (Per Profile)

| البيانات | يشتركون؟ | التوضيح |
|----------|---------|---------|
| **اسم الطبيب على الموعد** | ✗ | كل موعد يظهر باسم الملف الطبي المحدد له |
| **التخصص** | ✗ | كل ملف له تخصص منفصل |

#### هل يمكن فصل البيانات؟

إذا أردت أن **يفصل** الطبيب بين الملفات (يعني كل ملف يرى بياناته لوحده)، يجب:
- إنشاء **حساب مستخدم منفصل** لكل ملف طبي
- تسجيل الدخول بحساب مختلف لكل ملف

النظام الحالي يُعطي **نظرة موحدة** لجميع الملفات المرتبطة بنفس الحساب.
